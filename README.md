# Движок «Графа идеи» (idea-graph-engine)

Всё про проект и агентов, без интерфейса. Цепочка линейна: сфера → конкуренты → анализ → роли → сценарии → как есть → решение.

| Что | Как работает |
|---|---|
| `Project` | Граф (`idea-graph-core`) и банк знаний `knowledge` (конкуренты, факты, требования). Действия человека: принять, отклонить, удалить, написать своё, шаги диаграммы текстом |
| Исследователи | Три агента на разных моделях с веб-поиском ищут и анализируют сайты конкурентов; результаты объединяются без дублей |
| Помощник | Предлагает роли, сценарии, проблемы, варианты автоматизации и строит диаграммы. Добавляет только карточки «предложена»; в спорной ситуации задаёт один вопрос с вариантами и продолжает с ответом |
| Автопилот | Сильная модель: до 15 вопросов о границах системы (ответы — требования в банке), затем проходит цепочку сама, принимая и отклоняя предложения (`decide`) |
| Инструменты агентов | Помощник: `graph_apply` (только `add_card` нужных видов, диаграммы проверяются), `ask`, `finish`. Исследователь: `report`. Файлов и терминала нет |
| Запоминание | Отклонённое и удалённое не предлагается снова (`.idea-graph/flow.json`) |
| `diagrams.py` | Данные UML-диаграмм: последовательности (`parse_text`, `to_text`, `to_mermaid`) и вариантов использования |

Агенты запускаются через `agents.py`: Claude Code и OpenCode (модели подписки Go, усилие — вариант модели). Один ход — один запуск;
инструменты агент вызывает через MCP-мост `mcp_proxy.py`, который пересылает вызовы работающей оболочке.

Настройки (`~/.idea-graph/settings.json`, папка меняется переменной `IDEA_GRAPH_HOME`): помощник, автопилот, три исследователя, корневая папка проектов.

## Выгрузка документации и проверка согласованности

Три кнопки. Документ — только отражение графа, поэтому разногласия исправляются в графе до выгрузки.

- «Выгрузить .md» (`export_md`): сразу записывает `Документация.md` в папке проекта по текущему графу. Без проверки и без модели.
- «Проверить и выгрузить» (`export`): независимая проверка, вопросы вам по каждому разногласию, потом файл.
- «Проверить и выгрузить автоматически» (`export_auto`): то же без вопросов, применяется рекомендованный вариант.

Как работает проверка:

- Проверяет модель из настройки «Проверяющий» (по умолчанию не та, что у помощника и автопилота; если совпадает — предупреждение).
- Код сам находит точное: пустое описание или важность, проблема без выбранного решения, роль вне сценариев, сценарий без ролей,
  устаревшие диаграммы. Проверяющий один раз за проход читает весь граф и сдаёт один отчёт: смысловые разногласия
  (ровно три вида: `boundary` — карточка нарушает конкретную границу, `duplicate`, `contradiction`) и ответы по пунктам кода.
  Отчёт с ошибкой пакет возвращает модели, и она исправляет его в том же ходе.
- Вопросы и варианты правок строит код по шаблонам, а не модель: «Вне границы 3: «…»», «Дубль: «A» и «B»», «Нет решения: «…»».
  Вопрос до 120 символов, варианты до 60, варианта «оставить» нет. Автомат применяет рекомендованный вариант: вне границ — убрать;
  из двух противоречащих или дублей — ту, что назвал проверяющий (хуже в границах, при равенстве — созданную позже); проблема без
  решения — лучший вариант, либо новые варианты, либо убрать проблему; пустую карточку — дописать или убрать.
- Диаграммы «как есть» и «как будет» в конце перестраиваются сами по итоговым проблемам и решениям, без вопроса.
- Проходов столько, сколько нужно: пока проход что-то правит, граф проверяется ещё раз; без правок — выгрузка. Фиксированного числа
  шагов нет. Остановка с ошибкой, только если проход ничего не смог применить или те же разногласия вернулись после правок.

## Единое пространство имён

Роли и компоненты — один список (`роль`, `attrs.type`: человек, внешняя система, компонент системы: Сайт, Админка, База данных).
Его определяют на шаге «Роли» до сценариев и диаграмм; без хотя бы одного компонента диаграммы не строятся. Участник любой диаграммы
«как есть» и «решение» — только имя из списка (регистр и пробелы приводятся к имени из списка, другие имена пакет отклоняет). Актёры
диаграммы вариантов использования — только люди и внешние системы. Старые диаграммы с «чужими» именами проверка находит и перестраивает.

## Границы: закрытый мир

Всё, что не разрешено явно какой-либо границей и не неотъемлемо нужно для разрешённого, вне системы и убирается. Автопилот задаёт
вопросы о границах, пока они не станут понятны (не больше 70; закончить можно раньше), «не ради вопросов» и с уточнениями. Закончить
можно, только отчитавшись по каждой теме (процессы, роли, функции посетителей и владельца, уведомления, интеграции, данные,
платформа, ограничения, исключения): что решено или почему неприменимо. Счётчика «из N» нет.

## Дубли между сценариями

При создании: возможность, уже построенная в другом сценарии, заново не предлагается; если она нужна нескольким сценариям и является
самостоятельной целью роли внутри границ — предлагается отдельным сценарием. При проверке перед выгрузкой дубль (в том числе в разных
сценариях) решается одним способом: остаётся карточка в сценарии, где это главная цель, а при равенстве — созданная раньше; вынос в
отдельный сценарий при проверке не делается, чтобы проверка не создавала новое содержание.

## Автопилот «по сценариям»

Галочка при запуске автопилота (`start autopilot each=true`). Конкуренты, анализ и все роли — как обычно; дальше сценарии по одному:
агент предлагает ОДИН следующий сценарий (или говорит «основное покрыто» и ничего не создаёт), автопилот принимает или отклоняет его,
сценарий проходит проблемы → «как есть» → решения → «решение», и только потом начинается следующий. Каждый следующий шаг видит,
что уже построено по прежним сценариям (проблемы и выбранные решения). Уже имеющиеся сценарии сначала доводятся по одному.
Проблема, для которой в границах нет решения, убирается из графа, а «как есть» перестраивается. Предохранитель: не больше 8
сценариев за прогон; два отклонённых подряд — остановка.

## Жёсткие правила при создании

Агент не может создать нарушающее правила: пакет отклоняет карточки с точным текстом, агент исправляет и повторяет.
Описание проблемы и варианта — до 250 символов. «Как есть»: каждая принятая проблема отмечена на шаге (`pain.what` — точное
название), других нет, шагов «сам себе» нет, не больше 12 шагов. «Решение»: каждый изменённый шаг называет решение (`by`),
каждое выбранное решение есть хотя бы в одном шаге. Вопросы агентов: вопрос до 120 символов, варианты до 60, без пояснений.
- В документе: границы, конкуренты (без находок анализа), роли, сценарии с проблемами, решениями и таблицами шагов, предложенное
  и не принятое — отдельным разделом.

## Стабильность

- Запуск работы агентов защищён блокировкой: два одновременных запуска невозможны (второй получает «Уже идёт работа агентов»).
- Журнал работы агентов: `.idea-graph/agents.log` (по строке JSON на ход: время, ход, агент, модель, секунды, стоимость, ошибка;
  текстов графа нет; свыше 1 МБ старый журнал переименовывается в `agents.log.1`).
- При открытии проекта оболочка показывает предупреждения (`Project.warnings()`): роли без типа, нет компонентов при наличии
  сценариев, диаграммы не соответствуют графу. Ничего не запрещается.
- Проверка перед выгрузкой читает граф одним снимком на проход (`Project.frozen()`): то, что нашёл код, и текст для проверяющего
  согласованы между собой.
